# Menu bar display, preferences and Fixed Rate — 1.0.0 validation

Scope: the menu bar display rework (custom `NSStatusItem`, four display styles, new
metrics), the preferences window that replaces the dropdown, and the Fixed Rate mode.
Plan and decisions: [menu-bar-display-plan.md](menu-bar-display-plan.md).
Label-geometry research this builds on: [menu-bar-label-validation.md](menu-bar-label-validation.md).

## What shipped

| Piece | Notes |
|---|---|
| Custom `NSStatusItem` | Replaces `MenuBarExtra`, which cannot tell a left click from a right click. Left → preferences window; right → Preferences… / every mode / Quit. |
| Preferences window | `NSWindow` + `NSHostingController`, left vertical tabs: Fans / General / Menu Bar / About. |
| Menu bar styles | Icon + numbers (temperature above, RPM below), temperature curve, RPM curve, both overlaid. |
| Metrics | `averageTemp` (mean of every sensor, battery included), `batteryTemp` (feels-like), `fanRPM` (mean of the fans whose `F{i}Ac` read succeeded). |
| Fixed Rate | A hands-off mode holding a chosen RPM, set with a slider over the fan's reported range; remembered across launches. |
| Alerts | Daemon unreachable and terminal hold on the Fans page; update-needed and update-available on the About page; the icon turns red while any alert is active. |
| Strings | 76 keys × en / zh-Hans / zh-Hant (Traditional generated by `scripts/update-traditional.swift`). |

## Automated validation

- `swift build` — clean, no warnings.
- `swift test --no-parallel` — **142 tests in 23 suites**, Debug.
- `swift test -c release --no-parallel` — same 142, Release.
- `scripts/setup.sh test` — unit tests, the disconnected-clients SIGPIPE
  regression, and the packaging resource checks.
- `AppState(startServices: false)` is used for the offscreen panel test, so nothing
  in the automated suite touches SMC or starts a monitor.

## Deliberately not validated (residual risk)

- **No installed background service** during development. The daemon-down,
  version-mismatch and update banners render, but were never driven by a real daemon,
  and no install/upgrade/upgrade-recovery path was exercised end to end.
- **The status item was never inspected on a real menu bar.** Automated runs are
  headless; colours, sizing and the red alert state come from pixel tests, not from
  looking at the item.
- **One machine only** (a single-fan M4). Two-fan RPM averaging, a Mac with no
  battery sensor, and non-M4 core-key mapping are covered by unit tests, not hardware.
- **Curves were exercised with synthetic history.** No live run over a configured
  window (e.g. 1 s × 3 min) was performed outside the unit tests.
- The curve styles do not yet draw real sparklines from a live daemon; the renderer
  and the history are complete and tested, but the two were only joined in tests.

## Known limits

- Two stacked numbers are ~8.5 pt on a 22 pt bar: legible but small. A single reading
  stays at the 14 pt menu bar font.
- A CLI terminal hold keeps its own banner until GUI Fixed Rate fully replaces that
  path (plan §8) — losing it early would leave the app silently not controlling.
- `averageTemp` includes the battery sensor, by decision (plan Q4).
- Curve styles are the only remaining justification for fast polling; the idle-CPU
  pass is a separate pre-release item (plan §11).

## Reproduce

```bash
swift build
scripts/setup.sh test                # Debug: unit + socket + packaging
scripts/setup.sh test --release      # same, Release build

# Visual check, no services needed:
.build/out/Products/Debug/SmartFanApp
# Offscreen panel images:
SMARTFAN_PREVIEW_DIR=/tmp/previews swift test --filter LocalizedPanelTests
```

> On a CommandLineTools-only toolchain, `swift test` additionally needs
> `-Xswiftc -plugin-path -Xswiftc /Library/Developer/CommandLineTools/usr/lib/swift/host/plugins/testing`
> (CI's macos-15 with Xcode does not).
